# Техническое задание: расширение браузера для сбора данных о товарах с Ozon

## 1. Назначение проекта

Разработать браузерное расширение для автоматического сбора информации о товарах из поисковой выдачи Ozon.

Основной сценарий использования: пользователь открывает поиск Ozon, просматривает результаты, прокручивает выдачу и переходит между страницами. Расширение автоматически обнаруживает появляющиеся карточки товаров, извлекает доступную информацию и сохраняет её локально.

Пользователю не требуется вручную открывать каждую карточку, копировать данные или запускать сбор для каждой страницы.

Собранные данные предназначены для последующего анализа: сравнения цен, поиска наиболее выгодных предложений, проверки соответствия товаров заданным критериям и выявления продавцов.

## 2. Поддерживаемые браузеры

Обязательная поддержка:
- Mozilla Firefox (актуальная стабильная версия).
- Google Chrome (актуальная стабильная версия).

Требования:
- Использовать стандартные WebExtensions API.
- По возможности поддерживать единую кодовую базу.
- Не использовать браузерные API, доступные только в одном из поддерживаемых браузеров, без соответствующей абстракции.
- Для Firefox предусмотреть совместимость с его реализацией Manifest V3.
- Подготовить инструкции по установке в обоих браузерах.

Рекомендуемый технологический стек:
- JavaScript или TypeScript.
- Manifest V3.
- Content scripts для извлечения данных со страниц Ozon.
- MutationObserver для обнаружения динамически загружаемых карточек.
- browser.storage.local / chrome.storage.local для хранения данных.
- Минимальный интерфейс popup для управления сбором и экспорта.

## 3. Основной пользовательский сценарий

1. Пользователь устанавливает расширение.
2. Открывает Ozon и выполняет поиск товаров.
3. При необходимости применяет фильтры Ozon.
4. Включает сбор данных через интерфейс расширения.
5. Просматривает выдачу обычным способом: прокручивает страницу, переходит на следующие страницы или изменяет фильтры.
6. Расширение автоматически обнаруживает новые карточки товаров и сохраняет их данные.
7. Пользователь видит количество обнаруженных и сохранённых товаров.
8. Пользователь останавливает сбор.
9. Экспортирует накопленные данные в CSV или JSON.

Сбор должен работать без необходимости открывать карточки товаров по одной.

Расширение должно сохранять данные при переходах между страницами выдачи и перезагрузке вкладки.

## 4. Сбор данных

### 4.1. Обязательные поля товара

Для каждой обнаруженной карточки собирать:

| Поле | Описание |
|---|---|
| product_id | Идентификатор товара Ozon, если доступен |
| url | Прямая ссылка на карточку товара |
| title | Полное название товара |
| price | Основная отображаемая цена |
| original_price | Зачёркнутая цена, если присутствует |
| discount | Размер скидки, если явно отображается |
| volume | Объём товара, если можно достоверно определить |
| quantity | Количество единиц в упаковке, если указано |
| seller | Название продавца, если отображается |
| rating | Пользовательский рейтинг |
| review_count | Количество отзывов |
| availability | Информация о наличии, если отображается |
| collected_at | Дата и время обнаружения карточки |
| source_url | URL страницы поиска, с которой получены данные |

Если поле отсутствует или не может быть надёжно извлечено, сохранять null. Не подставлять предполагаемые значения.

### 4.2. Цены

Необходимо различать:
- обычную отображаемую цену;
- зачёркнутую цену;
- цену со скидкой;
- цену, доступную только при оплате определённым способом или с использованием подписки, если она отображается.

Не смешивать разные типы цен.

Если карточка показывает несколько цен, необходимо сохранить их в отдельных полях с указанием типа и условий получения.

В MVP достаточно сохранять основную цену и зачёркнутую цену. Расширенную модель цен предусмотреть архитектурно.

Все денежные значения должны храниться числом, без символов валюты и разделителей разрядов. Валюту сохранять отдельно.

### 4.3. Объём и количество

Расширение должно по возможности извлекать объём и количество товаров из названия или характеристик карточки.

Примеры:
- Elmex, 75 мл → volume = 75, unit = ml, quantity = 1.
- Elmex, 2 × 75 мл → volume = 75, unit = ml, quantity = 2.
- Elmex, набор из 3 штук → quantity = 3, volume = null, если объём не указан.

Не следует автоматически считать, что любое упоминание числа в названии является объёмом или количеством.

Если информация неоднозначна, сохранять исходное название и оставлять нормализованные поля пустыми.

### 4.4. Идентификация товара

Основной ключ дедупликации:
1. product_id Ozon.
2. Если product_id недоступен — нормализованный URL карточки.

Необходимо учитывать, что:
- один товар может встречаться на разных страницах выдачи;
- один товар может отображаться в разных поисковых запросах;
- разные товары могут иметь похожие названия;
- разные варианты товара могут иметь отдельные идентификаторы.

Нельзя объединять товары только по совпадению названий.

При повторном обнаружении существующего товара обновлять данные согласно выбранной политике обновления, но не создавать дубликат.

Рекомендуется сохранять историю наблюдений отдельно от актуального состояния товара.

## 5. Обнаружение карточек

Расширение должно поддерживать динамическую выдачу Ozon.

Основной механизм:
- первоначальное сканирование DOM после загрузки страницы;
- наблюдение за изменениями DOM через MutationObserver;
- обнаружение новых карточек при прокрутке;
- повторное сканирование после переходов по страницам;
- защита от повторной обработки одних и тех же DOM-элементов.

Необходимо предусмотреть:
- ленивую загрузку изображений и карточек;
- динамическое обновление выдачи;
- изменение фильтров;
- переходы по пагинации;
- возврат на предыдущую страницу;
- перезагрузку вкладки.

Не использовать агрессивный polling с высокой частотой.

Предусмотреть ограничение частоты обработки DOM, чтобы не ухудшать производительность Ozon.

## 6. Управление сбором

Popup расширения должен содержать:

- статус сборщика: включён / выключен;
- кнопку начала сбора;
- кнопку остановки сбора;
- количество обнаруженных карточек;
- количество уникальных товаров;
- количество карточек с ошибками извлечения;
- кнопку экспорта;
- кнопку очистки накопленных данных.

Дополнительно желательно отображать:
- текущий URL поисковой выдачи;
- время начала сбора;
- последнюю успешную операцию извлечения.

Сбор должен быть управляемым: пользователь явно запускает и останавливает его.

Не начинать сбор автоматически при каждом посещении Ozon без согласия пользователя.

## 7. Хранение данных

Данные должны храниться локально в браузере.

Требования:
- использовать browser.storage.local или chrome.storage.local;
- сохранять результаты между сессиями браузера;
- не отправлять данные на внешние серверы;
- не передавать данные третьим лицам;
- предусмотреть обработку ошибок записи и восстановления состояния.

Для большого количества товаров необходимо учитывать ограничения browser.storage.local.

Рекомендуется предусмотреть пакетную запись и разделение данных на логические сущности:
- товары;
- наблюдения товаров;
- сессии сбора.

Если объём данных окажется слишком большим для выбранного хранилища, допускается использование IndexedDB.

### 7.1. Сессии сбора

Каждый запуск сбора должен иметь отдельный идентификатор сессии.

Для сессии хранить:
- session_id;
- started_at;
- finished_at;
- начальный URL;
- поисковый запрос, если его можно достоверно определить;
- количество обнаруженных карточек;
- количество уникальных товаров;
- количество ошибок.

Должна быть возможность экспортировать данные одной сессии или всех сессий.

## 8. Экспорт

Обязательные форматы:
- CSV (UTF-8, желательно с BOM для корректного открытия в Excel).
- JSON.

CSV должен содержать одну строку на товар. Для истории наблюдений можно предусмотреть отдельный CSV-файл.

JSON должен сохранять полную структуру данных, включая null и метаданные сбора.

Экспорт должен выполняться непосредственно в браузере, без внешнего сервера.

Имя файла должно включать дату экспорта, например:

ozon-products-2026-11-11.csv

При экспорте CSV:
- корректно экранировать кавычки, запятые и переносы строк;
- не допускать потери кириллицы;
- цены экспортировать в числовом формате;
- URL экспортировать полностью.

## 9. Проверка качества данных

Расширение должно фиксировать качество извлечения.

Для каждой карточки желательно сохранять:
- extraction_status: success / partial / failed;
- extracted_fields — список успешно извлечённых полей;
- extraction_errors — список проблем;
- extraction_version — версия логики парсинга.

Необходимо отличать:
- поле отсутствует в карточке;
- поле присутствует, но не удалось извлечь;
- поле извлечено успешно.

Не подменять неизвестные значения нулями или пустыми строками без явного указания.

Предусмотреть возможность последующего анализа карточек с неполными данными.

## 10. Фильтрация и область действия

В MVP расширение должно работать на страницах Ozon с поисковой выдачей и каталогами товаров.

Ограничить доступ к страницам доменами Ozon, необходимыми для работы.

Не собирать данные с других сайтов.

Не открывать карточки товаров автоматически в фоновом режиме.

Не выполнять покупку, добавление в корзину, авторизацию или другие действия от имени пользователя.

В перспективе можно добавить фильтрацию по поисковому запросу, категории и заданным критериям, но первоначально расширение должно собирать все обнаруженные карточки независимо от их соответствия запросу.

## 11. Устойчивость к изменениям Ozon

Разметка Ozon может меняться.

Поэтому:
- логику извлечения отделить от UI расширения;
- селекторы и правила извлечения централизовать;
- предусмотреть несколько способов обнаружения карточки;
- не привязываться к одному CSS-классу, если есть более устойчивые признаки;
- при изменении структуры страницы не допускать массового сохранения некорректных данных;
- при низком качестве извлечения показывать предупреждение пользователю.

По возможности использовать структурированные данные страницы (JSON-LD и другие доступные данные), если они содержат актуальные сведения о товаре. Однако основным источником данных для MVP остаётся отображаемая пользователю карточка.

Не использовать внутренние API Ozon, если это требует обхода авторизации, антибот-защиты или иных технических ограничений. Не обходить CAPTCHA и ограничения доступа.

## 12. Производительность

Требования:
- не блокировать прокрутку страницы;
- не создавать заметных задержек при загрузке выдачи;
- обрабатывать карточки асинхронно и пакетами;
- исключать повторную обработку DOM-элементов;
- не выполнять тяжёлые операции в основном потоке страницы;
- корректно работать при сборе от 100 до 1000 и более уникальных товаров.

Проверить использование памяти и хранилища на выборках из 100, 500 и 1000 товаров.

## 13. Безопасность и приватность

- Не запрашивать избыточные разрешения браузера.
- Не использовать удалённый исполняемый код.
- Не передавать собранные данные на внешние серверы.
- Не собирать пароли, cookies, токены или личную информацию пользователя.
- Не изменять содержимое карточек и поведение сайта.
- Не обходить ограничения Ozon.
- Все данные должны оставаться под контролем пользователя.

## 14. Архитектура проекта

Рекомендуемое разделение:

- manifest — настройки расширения и разрешения;
- content — обнаружение карточек и извлечение данных;
- parser — нормализация названий, цен, объёмов и количества;
- storage — локальное хранение, дедупликация и история наблюдений;
- background — управление состоянием сборщика и обмен сообщениями;
- popup — интерфейс управления;
- export — формирование CSV и JSON;
- adapters — браузерные различия Firefox/Chrome;
- tests — модульные и интеграционные тесты.

Логику парсинга Ozon не смешивать с браузерной инфраструктурой.

## 15. Тестирование и критерии приёмки

### 15.1. Функциональные проверки

1. Расширение обнаруживает карточки при первоначальной загрузке выдачи.
2. Расширение обнаруживает карточки, появившиеся после прокрутки.
3. Расширение обнаруживает карточки после перехода на следующую страницу.
4. Повторно обнаруженные товары не создают дубликатов.
5. После перезагрузки вкладки ранее собранные данные сохраняются.
6. После перезапуска браузера данные сохраняются.
7. Пользователь может остановить и возобновить сбор.
8. CSV корректно открывается в Excel и содержит кириллицу.
9. JSON содержит все доступные поля.
10. Расширение не собирает данные с посторонних сайтов.

### 15.2. Проверка точности

Подготовить контрольную выборку минимум из 30 карточек разных типов:
- обычный товар;
- товар со скидкой;
- товар с зачёркнутой ценой;
- товар с ценой по специальным условиям;
- набор из нескольких единиц;
- товар с объёмом в названии;
- карточка без рейтинга;
- карточка без информации о продавце;
- карточка с длинным названием.

Сравнить результат извлечения с тем, что реально отображается в браузере.

Критерии:
- URL и идентификатор товара — 100% корректности для карточек, где они доступны.
- Цена — не менее 98% корректности среди карточек с однозначно отображаемой ценой.
- Название — не менее 98% корректности.
- Неизвестные значения не должны ошибочно подменяться предполагаемыми.
- Не должно быть ложного объединения разных товаров.

### 15.3. Нагрузочная проверка

Проверить сбор:
- 100 уникальных товаров;
- 500 уникальных товаров;
- 1000 уникальных товаров.

Убедиться, что:
- браузер остаётся отзывчивым;
- данные не теряются;
- дубликаты не накапливаются;
- экспорт завершается корректно.

### 15.4. Совместимость

Проверить функциональность в актуальных стабильных версиях Firefox и Chrome.

8. Краткий отчёт о проверке точности на контрольной выборке.

Расширение должно устанавливаться локально без публикации в официальных магазинах браузеров.

## 17. Приоритеты реализации

### MVP — обязательно

- Поддержка Firefox и Chrome.
- Сбор карточек из поисковой выдачи Ozon.
- Обнаружение динамически подгружаемых карточек.
- Извлечение основных полей.
- Дедупликация.
- Локальное хранение.
- Счётчик собранных товаров.
- Экспорт CSV и JSON.
- Управление запуском и остановкой сбора.

### Второй этап

- История изменения цен.
- Раздельное хранение сессий.
- Расширенная обработка специальных цен.
- Дополнительная нормализация характеристик товаров.
- Экспорт с фильтрами.
- Отображение статистики качества извлечения.
- Восстановление незавершённой сессии.

## 18. Важные ограничения

Расширение должно собирать только информацию, которая реально доступна в загруженной странице Ozon.

Оно не должно:
- утверждать, что просмотрело всю выдачу, если пользователь фактически не загрузил все страницы;
- считать карточку проверенной, если данные извлечены частично;
- самостоятельно открывать сотни карточек;
- имитировать действия пользователя для обхода ограничений;
- подставлять отсутствующие цены, рейтинги или характеристики.

Количество уникальных собранных товаров должно отражать фактически обнаруженные карточки, а не заявленное количество результатов поиска Ozon.

**Главный критерий успеха проекта:** пользователь может обычным образом просмотреть 100–1000 карточек в выдаче Ozon, а расширение автоматически сформирует структурированный набор данных с прямыми ссылками на товары, достаточный для последующего сравнения и проверки предложений.

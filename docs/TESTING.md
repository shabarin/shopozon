# Тестирование и нагрузочные проверки

## Окружение

- Node.js 24.15 (нативная поддержка TypeScript без сборки для тестов)
- macOS (darwin), 2026-11-11
- `jsdom` для DOM-тестов, `node:test` для запуска
- Хранилище в тестах и benchmark: `MemoryStore` (in-memory, JSON-клонирование)
- Браузерные сборки: esbuild, Chrome MV3 / Firefox MV3

## Команды

```bash
npm run typecheck      # tsc --noEmit, включая тесты и scripts
npm test               # все unit/integration тесты
npm run test:coverage  # покрытие (Node experimental coverage)
npm run accuracy       # точность на 36 контрольных карточках
npm run bench          # 5000 товаров по умолчанию
BENCH_PRODUCTS=100 npm run bench
npm run build          # сборка Chrome/Firefox + ZIP
npm run verify         # typecheck + tests + build
```

Всего: **28 тестов** (на момент отчёта), все проходят.

## Результаты нагрузочного теста

Скрипт: `scripts/storage-bench.ts`. Для каждой выборки — уникальные товары, импорт пакетами
по 100, затем полный экспорт (bundle + оба CSV + JSON). Числа — медиана одного прогона на
указанном окружении и **не являются** измерением скорости `chrome.storage.local`.

| Товаров | Наблюдений | Ключей в хранилище | Импорт | Экспорт | CSV товары | CSV наблюдения | JSON |
| ---: | ---: | ---: | ---: | ---: | ---: | ---: | ---: |
| 100 | 100 | 106 | 6 мс | 12 мс | 44 KiB | 42 KiB | 287 KiB |
| 500 | 500 | 514 | 21 мс | 27 мс | 217 KiB | 208 KiB | 1.44 MiB |
| 1000 | 1000 | 1024 | 39 мс | 43 мс | 434 KiB | 415 KiB | 2.87 MiB |
| 5000 | 5000 | 5104 | 187 мс | 194 мс | 2.12 MiB | 2.08 MiB | 14.4 MiB |

Импорт: 17–27 тыс. карточек/с в MemoryStore. Рост линейный, память и число ключей растут
пропорционально числу товаров и чанков.

### Что это значит

- Алгоритмы дедупликации и чанковой записи не имеют квадратичной деградации на 1000+ товарах.
- Индекс товаров (`pidx:<n>`) и наблюдения (`obs:<session>:<n>`) пишутся чанками по 100,
  поэтому одна пакетная запись не переписывает всю базу.
- Реальная скорость будет ниже из-за сериализации `storage.local`, но объём одной записи
  ограничен пакетом (до 100 карточек) и несколькими чанками.
- JSON для 5000 товаров занимает ~14 MiB; при очень больших базах используйте экспорт по
  сессиям или переходите на IndexedDB.

## Проверка в Firefox (локально)

Дата: 2026-11-12. Окружение: macOS, Mozilla Firefox 160.0, geckodriver 0.37.1,
headless-режим. Использовалась сборка `dist/firefox`, установленная как временное дополнение.

Чтобы проверить content script без реального Ozon, применялась отдельная тестовая копия
манифеста с дополнительным `http://*.ozon.ru/*` и локальный mock-сервер. DNS в тестовом
профиле (`network.dns.localDomains`) направлял `www.ozon.ru` на loopback. Production-манифест
при этом остаётся HTTPS-only; в тестовой копии менялись только `host_permissions` и
`content_scripts.matches`.

Проверено в реальном Firefox:

- popup загружается, кнопки «Начать сбор»/«Остановить» работают;
- первоначальное сканирование mock-выдачи: 3 карточки;
- карточка, добавленная после загрузки, обнаружена через `MutationObserver`;
- SPA-переход через `history.pushState` + `popstate` обработан;
- 5 уникальных товаров, 0 ошибок извлечения; повторные карточки не создали дубликатов;
- товар без числового id дедуплицирован по нормализованному URL;
- поля `title`, `price`, `original_price`, `volume`, `quantity`, `seller`, `rating`,
  `review_count`, `availability` извлечены корректно; десятичная цена `1 234,50` сохранена
  как `1234.5`;
- остановка сбора переводит сессию в `stopped`, `enabled = false`, активная сессия сбрасывается;
- экспорт CSV: BOM, CRLF, кириллица, колонка `discount_text`, число строк = 5 товаров + заголовок;
- экспорт JSON: 5 товаров, 9 наблюдений, 1 сессия;
- очистка удаляет товары, наблюдения и сессии.

Итог: **PASS**. Живой Ozon из тестового окружения вернул HTTP 403, поэтому реальные селекторы
по-прежнему требуют ручной проверки по чек-листу ниже. Chrome в этой среде не запускался:
его сборка проверяется статически (`web-ext`-аналога для Chrome нет) и типовыми тестами.

## Проверки приёмки (ручные, в браузере)

Автотесты не заменяют проверку на живом Ozon. Чек-лист:

1. Загрузить `dist/chrome` (Chrome) и `dist/firefox/manifest.json` (Firefox).
2. Открыть поиск Ozon, запустить сбор, убедиться, что карточки появляются при загрузке.
3. Прокрутить 2–3 экрана — счётчик должен расти без дублей.
4. Перейти на следующую страницу/применить фильтр — сбор продолжается.
5. Перезагрузить вкладку — данные сохраняются, сбор продолжается (если был включён).
6. Остановить сбор, перезапустить браузер — сбор не запускается автоматически, сессия
   помечена `interrupted`, данные на месте.
7. Экспортировать CSV и JSON; открыть CSV в Excel — кириллица, цены, кавычки, запятые,
   переносы строк корректны.
8. Проверить, что на не-Ozon сайте расширение не активно и не собирает данные.
9. Проверить, что расширение не открывает новые вкладки/карточки и не меняет DOM.
10. Сверить 5–10 карточек с тем, что отображается на странице.

## Что не проверено автоматически

- Реальные селекторы Ozon (разметка может измениться в любой момент).
- Поведение Chrome MV3 service worker при длительном простое (логика восстановления состояния
  покрыта тестами репозитория, но не браузерным E2E).
- Ограничения квоты `storage.local` в конкретной версии браузера.
- Firefox E2E с постоянной установкой/подписью (проверялась временная загрузка).
- Chrome: в этой среде браузер не запускался по требованию заказчика; сборка и манифест
  проверены статически, поведение — общими unit/integration тестами и Firefox E2E.

Для E2E можно использовать Playwright с загруженным расширением, но это требует отдельного
CI-окружения и реального аккаунта/региона Ozon; в рамках проекта выполнены unit/integration
тесты и локальный Firefox E2E на mock-выдаче.

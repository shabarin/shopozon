# Отчёт о точности извлечения

Дата генерации: 2026-11-11  
Версия парсера: `1.0.0` / `1.0.0-dom.1`  
Команда: `npm run accuracy`

## Методика

Используется контрольная выборка из **36 синтетических карточек** (`tests/fixtures/cards.ts`),
повторяющих разметку Ozon: обычный товар, скидка, зачёркнутая цена, Ozon Карта, подписка,
наборы, объём/вес, длинное название, отсутствие рейтинга/продавца/цены, неоднозначный объём,
JSON-LD fallback и др. Каждая карточка имеет ожидаемые значения; тест сравнивает их с
результатом `extractCard` на DOM, собранном через `jsdom`.

Команда `npm run accuracy` печатает отчёт и завершается с ошибкой, если:

- URL или `product_id` точнее не 100%;
- название или цена точнее менее 98%;
- ожидаемые `null` заменены значениями.

## Сводка по 36 карточкам

- Успешно (`url` + `title` + `price`): **33**
- Частично: **3** (без цены — это корректные карточки с ценой по запросу / без цены)
- Неудачно: **0**
- Корректных `null`-значений: **9/9 (100%)**

## Проверенные сценарии

- обычная карточка с ценой, рейтингом, отзывами, продавцом и наличием;
- скидка и зачёркнутая цена (включая `1 234,50 ₽` и неразрывные пробелы);
- цена с Ozon Картой и цена «без Ozon Карты» в одной карточке;
- цена по подписке и платёж `₽/мес` (не становится основной ценой);
- наборы `2 × 75 мл`, `75 мл × 3`, `набор из 3 штук`;
- вес `500 г`, объём `1 л` и `0,75 л`;
- диапазон `100–200 мл` → `volume = null`, состояние `failed`;
- `1000 МЕ` → не объём и не количество;
- карточка без рейтинга/продавца/цены → соответствующие `null`;
- длинное название сохраняется полностью;
- название из `img[alt]` при отсутствии текстовой ссылки;
- цена «по запросу» → `price = null`, состояние `failed`;
- JSON-LD заполняет только отсутствующие цену/рейтинг/отзывы;
- бейдж «Хит» не приклеивается к названию;
- процент в названии («Масло 10%») не считается скидкой;
- ссылка без числового id → дедупликация по URL.

## Дедупликация и история

Отдельные тесты (`tests/storage.test.ts`) проверяют:

- повторное обнаружение товара по `product_id` не создаёт дубликат;
- карточка без числового id дедуплицируется по нормализованному URL (query/hash отбрасываются);
- разные названия не объединяются; ключ — только id или URL;
- `null` при повторном наблюдении не стирает ранее известные значения;
- каждое обнаружение сохраняется в истории наблюдений отдельно;
- повторная отправка (`is_update`) не увеличивает счётчик обнаруженных карточек;
- качественный guard отклоняет пакет при массовом провале;
- 1000 товаров сохраняются и экспортируются без потерь и дубликатов.

## Ограничения методики

Это **регрессионный** отчёт, а не измерение точности на живом Ozon:

- разметка синтетическая и не учитывает региональные, A/B и авторизационные варианты;
- цены с Ozon Картой/подпиской зависят от аккаунта пользователя;
- реальные карточки могут содержать рекламные блоки, видео, несколько продавцов и другие
  варианты, которых нет в выборке;
- рейтинг/отзывы могут отсутствовать у новых товаров — это не ошибка извлечения.

Перед публикацией выполните ручную проверку на живой выдаче по чек-листу из README
(«Проверка на живом Ozon»). Если появились расхождения, добавьте карточку в fixtures и
обновите селекторы по [SELECTORS.md](SELECTORS.md).

## Как воспроизвести

```bash
npm install
npm run accuracy
npm test
```

Отчёт печатает таблицу в stdout. Тест `tests/extractor.test.ts` дополнительно проверяет
согласованность `field_states` с фактическими значениями: поле не может быть помечено
`extracted`, если значение `null`.
